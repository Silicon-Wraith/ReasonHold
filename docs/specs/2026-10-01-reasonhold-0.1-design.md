## 1. Purpose

ReasonHold tells an agent what it should believe about the git checkout it is working in. Documentation search answers "what is similar?"; ReasonHold answers "what should I believe?" along three axes:

| Axis | Question | Requirements |
|---|---|---|
| Scope | Which documents govern this path? | R-01 to R-05 |
| Time | Which documents and decisions are still true? | R-06 to R-09 |
| Rank | Which source wins when two disagree, and do they disagree? | R-10, R-11 |

ReasonHold also keeps the project's decision log. It never generates text: every answer traces to a committed document, decision record, manifest entry or pending record. Judgment happens in the calling agent, which writes through ReasonHold's tools.

Out of scope for 0.1:

- LanceDB or any storage abstraction (Weaviate only until adoption needs an embedded store; an interface is introduced then).
- Copy-on-branch indexing (full re-index per branch until timing becomes a problem).
- A Serena code-navigation adapter (the seam is built, the adapter is not).
- Text generation, AgentOS, Nebulon as a consumer, PyPI publication.
- Any market-research claim (novelty, pricing, free-tier limits, positioning) in the README before the operator's research is folded in.

## 2. Repository, consumers and exit criterion

**Repository.** `Silicon-Wraith/ReasonHold`, MIT, Python 3.11 or newer. Work happens on feature branches; pull requests are merged by the operator, never by an agent.

**Exit criterion for 0.1.** Two projects with different layouts run on ReasonHold:

1. **Ariadne.** Its vendored `docs-rag/` is removed after Auctor's five deletion criteria are met. Its 202-record decision log moves from `docs-rag/decisions.jsonl` to `decisions.jsonl` at the repository root with `git mv` (records byte for byte unchanged, so derived ids are stable), and its `sync-doc.yaml` is read unchanged under the legacy name. Its index is rebuilt with `qwen3-embedding:0.6b`.
2. **Sendesis.** A new `reasonhold.yaml` generated by `reasonhold init`, a new `decisions.jsonl`, the MCP entry and the SessionStart hook.

Running both proves R-22's point: a project declares its own documentation layout and authority ladder in the manifest without editing ReasonHold's code (R-10, R-18).

**What moves in from Auctor.** `docs/architecture/requirements.md`, `docs/reviews/2026-09-23-origin-extraction-triage.md`, and Auctor's 8 decision records, copied unchanged into this repository's `decisions.jsonl`. Changes this design makes to them are new records with `supersedes_records`, never edits (section 9). `ORIGIN.md` stays in the Auctor folder, frozen and gitignored; triage rows resolved by this spec are updated during implementation.

**Source of extraction.** Ariadne's `docs-rag/` (the most hardened copy; Auctor's copy is an older snapshot).

## 3. Source-of-truth files

Three files in the user's repository, committed and read the same way on every branch. Each has a JSON Schema; `reasonhold check` validates all three, and the indexer refuses to run on an invalid manifest.

### 3.1 Manifest: `reasonhold.yaml` (legacy name `sync-doc.yaml`)

A superset of Ariadne's format, so an existing `sync-doc.yaml` keeps working unchanged.

Unchanged keys and rules:

- `global`: `checks`, `docs`, `archival`, `index`.
- `areas.<name>`: `description`, `projects`, `docs`, `index`, `checks`.
- `checks.<name>`: `description`, `mode` (`index` or `fs`), `reads`, `validates_against`. The `reads` to `validates_against` binding is the document-to-code mapping (decision `doc-code-mapping-lives-in-checks` in Ariadne).
- Placement is declared, never inferred (R-01). `projects`, `docs` and `index` are non-empty lists. Area order matters (first match wins). Files are gathered with recursive globs and attributed with single-level matching; both engines' behaviour is kept and tested.

New keys:

```yaml
project:
  id: ariadne                      # used for collection naming; default: repository directory name
  decisions: decisions.jsonl     # default: decisions.jsonl at the repository root
  pending: reasonhold.pending.jsonl     # default: next to the manifest
  embedding:
    provider: ollama               # ollama | openai_compatible
    model: qwen3-embedding:0.6b
    base_url: http://localhost:11434
  index:
    branch_isolation: true         # false: default branch only (single-collection deployments)

authority:                         # ordered, highest first (R-10)
  - level: architecture
    paths: ["docs/architecture/**"]
    weight: 0.08
  - level: implementation-spec
    paths: ["docs/specs/**"]
    weight: 0.06
  # ...
```

When `authority` is absent (every legacy `sync-doc.yaml`), a built-in default ladder equal to today's Ariadne ladder applies, so Ariadne's ranking does not change. Entries may also set `document_kind`. Reranker weights come from the ladder instead of code.

ReasonHold edits the manifest only for mechanical curation and candidate promotion (section 6), through a comment-preserving YAML round trip (`ruamel.yaml`).

### 3.2 Decision log: `decisions.jsonl`, append-only

Existing fields are kept: `topic`, `decision`, `rationale`, `alternatives_considered`, `datetime`, `session_context`, `tags`, `status`, `supersedes` (document retractions, `path` plus optional `#section`, matched as a case-insensitive substring of the section heading; R-07).

New fields:

- `id`: `dec-` followed by the first 12 hex digits of `sha256(topic + "|" + datetime)`. Written explicitly on new records; derived the same way for records that have none. The file is never rewritten to add ids.
- `supersedes_records`: list of record ids this decision retires (closes the R-06 gap).
- `provenance`: `{kind: human | agent | sendesis_run, actor?, run_id?, role?}`.
- `resolves`: list of pending-record ids this decision resolves (section 6.3).

Status is computed, never edited: a record is superseded when it was written with `status: superseded` or when a later active record lists its id in `supersedes_records`.

### 3.3 Pending sidecar: `reasonhold.pending.jsonl`, append-only

Agents and ReasonHold append here; humans never edit it. Every record has `id`, `kind`, `datetime` and `provenance`.

| kind | Fields | Written by |
|---|---|---|
| `candidate_binding` | `target` (check or area name), `reads`, `validates_against`, `reason` | `propose_binding` |
| `conflict` | `doc_a`, `doc_b` (path plus optional section), `paths` (governed paths in common), `claim`, `evidence_a`, `evidence_b` | `report_conflict` |
| `resolution` | `resolves` (ids), `outcome` (`promoted`, `rejected`, `resolved`), `decision_id?`, `note?` | `resolve`, `candidates promote/reject`, `store_decision(resolves=...)` |
| `path_alias` | `old_path`, `new_path` | mechanical curation |
| `curation` | `edit` (what changed in the manifest), `cause` (rename, deletion) | mechanical curation |

A `candidate_binding` or `conflict` is open until a `resolution` names it. Open records appear in `governing_docs` results and in the preamble. `path_alias` records let retractions recorded against an old path follow a moved document.

## 4. The derived index

**Identity: (project, branch).** ReasonHold answers about the checkout it runs in. Unmerged documents and retractions on a feature branch must never leak into answers for `main` or another branch, and exact queries must describe the code actually checked out.

- Branch comes from git; a detached HEAD uses `detached-<short sha>`.
- Collection name: `RH_<Project>__<branch slug>`, sanitized to `^[A-Z][A-Za-z0-9_]*$`, with a short hash suffix when too long or when two branches would collide.
- Each collection's Weaviate description records `project`, `branch`, `model_id`, `dims`, `manifest_sha256`, `indexed_commit` and `last_full_index`.

**Lifecycle.**

- First use in a worktree with no collection: a full index (about 90 s for Ariadne's 5,157 chunks with the default model, per the spike). A command that needs an index and finds none raises `IndexMissing` and names `reasonhold index`; it never answers from another branch's collection.
- Later runs are incremental per file (today's modification-time rule within a worktree), with the retraction overlay applied whenever a file is re-chunked.
- **Full re-index rule.** On every `reasonhold index`, a full re-index runs instead of an incremental one when any of these holds:
  1. A merge commit lies between `indexed_commit` and HEAD (`git rev-list --merges indexed_commit..HEAD` is non-empty).
  2. `indexed_commit` is not an ancestor of HEAD (rebase, reset, forced update).
  3. Since `indexed_commit`, the decision log gained retractions or `supersedes_records`, or the manifest's `authority` block changed.
- Queries never trigger indexing. Answers from a stale collection carry a warning naming the cause; absence checks (section 5) refuse instead.
- `--full` drops and recreates the collection (R-09).
- An index lock per collection (under the user cache directory) keeps a post-merge hook and a manual run from indexing the same collection at once.
- `reasonhold gc` lists the project's `RH_` collections whose branch no longer exists in the local repository and drops them after confirmation (`--yes` for scripts). It never touches other projects, unresolvable branches, or non-`RH_` collections.

**Single-collection mode.** `index.branch_isolation: false` indexes only the default branch (for Weaviate Cloud's one-collection free tier). Queries from another branch carry a warning that local changes are not reflected.

**Weaviate connection (R-14).** One connection factory with two modes: local (host, HTTP port, gRPC port) and Weaviate Cloud (cluster URL and an API key read from a named environment variable). No storage interface.

**Embedding (R-15, R-16).** A provider protocol `{embed(texts), dims, model_id}` with Ollama and OpenAI-compatible implementations over plain HTTP; batching and truncation belong to the provider. Default: Ollama with `qwen3-embedding:0.6b` (spike: at least as good as `qwen3-embedding:4b` on Ariadne's corpus, 2.5x smaller vectors, half the embedding time). The model guard compares recorded `model_id` and `dims` with the configured provider and refuses to query or extend on mismatch, naming `reasonhold index --full` as the fix.

**Corpus.** As today: documents and code from the manifest's `index` and area globs, chunked structurally (markdown, Python, C#, SQL, YAML, the manifest itself) plus one chunk per decision. Open pending records are indexed as searchable chunks but never treated as governing documents.

**Kept behaviour (R-17),** each pinned by the existing tests: `FIELD` tokenization of paths; insert first, then delete stale chunks; verified inserts with one retry; the binary-file guard; full re-index recreates the collection; schema drift raises instead of repairing; deterministic chunk UUIDs.

## 5. Operations

One Python API; the CLI, MCP server and Agno package wrap it. Every result reports the index it came from: branch, fresh or stale, and why.

**Belief.**

- `search_docs(query, top_k=5)`: semantic search with the reranker (weights from the manifest ladder). Each hit carries authority level, document kind, area, and any retraction (summary, decision id, date).
- `search_decisions(query, top_k=5, status="active" | "superseded" | "all")`: filters on the stored status property (R-12).
- `governing_docs(path)`: computed from the manifest only, no vector search (R-02). Returns every document governing the path, ordered by authority, each with its binding (check, area or global), its authority level, any active retraction, open conflicts and open candidate bindings involving it, and overlap hints (section 6.3).
- `retractions_for(path)`: active retractions affecting a document or section, following `path_alias` records.
- `decision(id)`: one record with its computed status and what superseded it.
- `conflicts(path=None, open_only=True)`.

**Exact (R-13).** Total recall, never vector search.

- `symbols(chunk_type, file_prefix=None, names_only=False)`, `inventory()`, `freshness()` (stale, not indexed, orphaned, empty, plus merge and history staleness).
- Any absence question raises `IndexStale` or `IndexMissing` rather than returning a misleading empty result.

**Writes.** Always appended.

- `store_decision(..., supersedes=None, supersedes_records=None, resolves=None, provenance)`: fixed order validate, embed, append, index. The derived id makes a retry idempotent. Every `supersedes_records` and `resolves` entry must name an existing id. Already-indexed chunks are annotated immediately, as today.
- `propose_binding(target, reads, validates_against, reason, provenance)`.
- `report_conflict(doc_a, doc_b, paths, claim, evidence_a, evidence_b, provenance)`.
- `resolve(pending_ids, outcome, decision_id=None, note=None, provenance)`.

**Governance.**

- `coverage()` (R-03): source paths no area covers; documents no area, global list or archival list places; indexed source files no binding matches. Source files are listed from git and the filesystem, not from code chunks.
- `curate(dry_run=True)`: mechanical manifest curation (section 6.1).
- `preamble(max_lines=60, max_bytes=4096)` (R-08): index state and staleness, active retractions, open conflicts, open candidates, in that priority order. Whole rows are dropped to fit, never truncated, with an "N most recent of M" footer. Always fails open.

**Errors.** `ManifestInvalid`, `IndexMissing`, `IndexStale` (raised only by absence checks; elsewhere staleness is a warning), `ModelMismatch`, `UnknownRecord`, `StoreUnavailable`.

**Code-index seam.** `symbols()` and the code half of `search_docs` (Python, C# and SQL chunks) sit behind one internal module; nothing else reads code chunks. A later release can replace that module with a Serena adapter and drop the code chunkers. `coverage()`, `curate()` and `governing_docs()` do not depend on code chunks, and retractions only name documents (R-07).

## 6. Curation and conflicts

### 6.1 Mechanical curation (automatic)

Only changes computable from git and the manifest. `reasonhold curate` runs at the start of every `reasonhold index`, and on its own. It reads renames and deletions from `git diff --find-renames` since `indexed_commit` plus the working tree:

1. **Renamed or moved document:** every manifest reference (`docs`, `reads`, `archival`, `global.docs`, explicit `index` entries) is updated to the new path, and a `path_alias` record is appended so retractions recorded against the old path still apply.
2. **Deleted document:** references are removed. If a list would become empty (the manifest forbids empty lists), the entry stays and `coverage()` reports a hole.
3. Nothing else is automatic. An unplaced new document or a new source module in no area is a judgment; it is reported by `coverage()` and waits for a candidate.

Each edit is applied with the comment-preserving round trip, logged as a `curation` record, and printed. Edits land in the working tree uncommitted.

This partly supersedes Auctor's `manifest-maintenance-detect-propose-confirm` (section 9): mechanical maintenance no longer waits for a human.

### 6.2 Judgment changes (through gates)

- Agents propose bindings with `propose_binding`: the Sendesis Architect when it writes a design for a module (R-05), the Doc Syncer when it finds an unbound document, and single-agent CLIs following the skill pack.
- Promotion happens where a human already is: a Sendesis design-approval gate promotes the candidates proposed in that run (matched by `run_id`); outside Sendesis, `reasonhold candidates promote <id>` and `reject <id>`.
- There is no MCP or Agno tool for promotion or rejection, so an agent cannot confirm its own proposal.
- Promotion adds the document to the target check's `reads` or the target area's `docs` (creating the check if new) and appends a `resolution` record.

### 6.3 Conflicts (R-11)

- **Overlap hints** are computed by `governing_docs(path)`: two unretracted documents at the same authority level governing the same path. A hint is a prompt to look, not a claim of disagreement, and is not stored.
- **Reported conflicts** come from agents (`report_conflict`) with both documents and sections, the disputed claim and quoted evidence from each.
- Open conflicts appear in `governing_docs` and the preamble until resolved.
- `store_decision(..., resolves=[conflict_id])` records the deciding decision and its resolution in one call. Usually the decision retracts the losing side through `supersedes`; a conflict can also be resolved as "both stand" with a rationale.

## 7. Delivery

**CLI: `reasonhold`.**

| Group | Commands |
|---|---|
| Setup | `init` (scaffold `reasonhold.yaml` from the detected layout), `check` |
| Index | `index [--full] [--dry-run]`, `curate [--dry-run]`, `freshness`, `inventory`, `gc [--yes]` |
| Belief | `search`, `govern <path>`, `decisions [search | show <id>]`, `conflicts` |
| Exact | `symbols`, `coverage` (exits non-zero on holes, for CI and git hooks) |
| Writes | `decide` (flags or JSON on stdin), `candidates [list | promote | reject]` |
| Session | `preamble [--format text | claude-hook]`, `mcp` (stdio server) |

**MCP server (stdio, R-20).** Tools: `search_docs`, `search_decisions`, `store_decision`, `list_indexed_files` (kept from R-12), plus `governing_docs`, `retractions_for`, `decision`, `conflicts`, `propose_binding`, `report_conflict`, `symbols`, `freshness`, `coverage`. Not exposed: `promote`, `reject` (human only), `index`, `curate`, `gc` (administrative and slow). Server instructions are generated from the project id (R-18).

**Preamble and hooks (R-08, R-21).** The preamble is plain command output. Shipped recipes: a Claude Code SessionStart hook (`reasonhold preamble --format claude-hook`, fail-open, 20 s timeout, no `jq`), and a git `post-merge` hook that runs `reasonhold index` in the background. Codex gets an `AGENTS.md` snippet that runs `reasonhold preamble` first, documented as unverified until verified (R-20). The documentation states that reading a file directly bypasses the retraction overlay.

**Skill pack (R-21).** The single-agent form of the discipline, as Claude Code `SKILL.md` files plus an `AGENTS.md` section for other CLIs: `session-bootstrap` (preamble and retraction discipline: retract only documents that assert the thing, never `src/` or `tests/`, a retraction is not a delete), `record-decision` (record a design's decisions at approval, with `supersedes`), `consult-before-design` (`governing_docs` and `search_decisions` first), `propose-and-report` (`propose_binding` when writing a design, `report_conflict` on a contradiction), `reindex` (when to index and what `--full` means). The full governance workflow belongs to Sendesis.

**`reasonhold[agno]`, module `reasonhold.agno`.** `ReasonHoldTools` (an Agno toolkit with the MCP tool set and the same exclusions), `ReasonHoldKnowledge` (Agno knowledge over `search_docs`, with retraction and authority fields), and `reasonhold_context(paths)` (a pre-run hook that injects the preamble plus the governing documents and retractions for the paths in scope). Agno pinned to 3.0.x.

**Packaging.** One distribution, `reasonhold`, console script `reasonhold`, optional extra `[agno]`. Dependencies: `weaviate-client` 4.x, `pyyaml`, `ruamel.yaml`, `fastmcp`. Embedding providers use plain HTTP. PyPI and `uvx` publication is the operator's decision.

## 8. Build order, testing and migration

**Build order.** Each step keeps the suite green.

1. **Seed.** Copy Ariadne's `docs-rag/` into `src/reasonhold/` as a package; the existing 189 tests pass before anything changes (R-17 parity gate).
2. **Identity and configuration.** Manifest `project` and `authority` blocks, legacy reader with the default ladder, (project, branch) collection identity and metadata, connection factory, single-collection mode.
3. **Embedding.** Provider protocol, Ollama and OpenAI-compatible providers, model guard, default `qwen3-embedding:0.6b`.
4. **Decision log.** Ids, `supersedes_records`, `provenance`, `resolves`, computed status, `store_decision` write-order fix, status-property filter.
5. **Index lifecycle.** `indexed_commit` and the full re-index rule, staleness warnings and refusals, `gc`, index lock.
6. **Governance.** Sidecar, `governing_docs`, overlap hints, conflicts, `coverage`, mechanical `curate`, promotion and rejection.
7. **Code-index seam.**
8. **Delivery.** CLI, MCP server, preamble and hook recipes, skill pack, `reasonhold[agno]`.
9. **Migration.** Sendesis, then Ariadne.

**Testing.**

- Unit tests run without network: manifest, decision log, sidecar, curation, preamble budget and governance logic, with fakes for Weaviate and Ollama.
- Integration tests, marked, run against the local Weaviate (port 8081) and Ollama with throwaway `RH_Test…` collections that are always removed: indexing, model guard, merge-triggered full re-index, `gc`, MCP over stdio.
- The spike's 40 questions become a retrieval benchmark run with the integration tests, reporting hit@5 and MRR. It informs; it does not gate.

**Migration.**

- **Sendesis:** `reasonhold init` produces a manifest covering `docs/specs`, `docs/plans`, `roles/`, `schemas/` and `CLAUDE.md` with its own authority ladder; a new `decisions.jsonl` seeded with the system vision spec's 22 decisions; MCP entry and SessionStart hook.
- **Ariadne** (on a feature branch in Ariadne): point `.mcp.json` and the SessionStart hook at `reasonhold`; update its 10 skills from `docs-rag/...` script paths to `reasonhold` commands; move the decision log to the repository root with `git mv` (unchanged records); re-index into `RH_Ariadne__main` with the default model; record the extraction as a decision in Ariadne's log without `supersedes` (triage action 4); remove `docs-rag/` once Auctor's deletion criteria are met. The old `AriadneDoc`, `AuctorDoc` and `ProjectDoc` collections are left for the operator to drop.

## 9. Decisions recorded with this spec

Appended to `decisions.jsonl` with this spec, after Auctor's 8 records:

| Topic | Effect |
|---|---|
| `project-renamed-reasonhold` | The project is ReasonHold. Retracts nothing; Auctor-named documents are history. |
| `manifest-curation-mechanical-auto-judgment-via-gates` | Supersedes `dec-34e0d8d29439` (`manifest-maintenance-detect-propose-confirm`) in part: mechanical edits are automatic; judgment bindings still need a human, at a gate or by command. |
| `pending-records-in-sidecar-jsonl` | Candidates and conflicts live in `reasonhold.pending.jsonl`, answering the requirements' open question. |
| `conflicts-reported-by-agents-tracked-by-reasonhold` | Answers R-11's open mechanism. |
| `index-per-project-and-branch` | Collection per (project, branch); full re-index on branch creation, after merges and after history rewrites; copy-on-branch deferred. |
| `default-embedding-qwen3-0.6b` | Default embedding model, per the spike; answers the open default-provider question in `dec-51f16d15212d`. |
| `weaviate-stays-lancedb-interface-later` | Reaffirms `dec-8421c3264745`: an interface is introduced only when adoption needs an embedded store. |
| `spikes-before-spec-research-before-release` | Changes the Auctor sequence: architecture spikes now, market research as a pre-release gate. |
| `consumers-ariadne-and-sendesis` | 0.1 exits on Ariadne and Sendesis; Nebulon later. |
